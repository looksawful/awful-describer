# Engineering Audit — 2026-09-09

## Scope

Deep audit of Awful Describer covering TypeScript correctness, Electron privilege boundaries, Ollama lifecycle, renderer state/queue behavior, file/preview handling, Windows compatibility, dependencies, testing, CI, repository hygiene, and agent/documentation readiness.

Repository baseline at audit start: one initial commit, no tests, no CI, no README, no issues, mostly TypeScript/TSX with `strict: true`, plus JavaScript Tailwind/PostCSS configuration.

## Executive assessment

The product concept and component structure are small enough to recover cleanly, but the initial `v1.0.0` engineering baseline was not release-grade. The largest risks were not visual: unverified build health, duplicated IPC contracts, shell-string process operations, broad Ollama process termination, ineffective cancellation, stale renderer code that failed strict TypeScript, obsolete Windows probes, and a legacy Electron/dependency tree.

The TypeScript-hardening branch addresses the highest-confidence problems while deliberately deferring the Electron major upgrade and dependency-tree modernization until a green reproducible baseline exists.

## Findings and disposition

### P0 — Reproducibility and TypeScript baseline

**Finding:** No test script, lint/quality gate, CI workflow, or commit status existed. Strict TypeScript was configured but not demonstrably passing. `KeyboardShortcuts.tsx` referenced a non-existent `selectedImage` store field.

**Action:** Added explicit renderer/main/node/test typechecks, `node:test` unit tests, aggregate `npm run check`, Windows GitHub Actions, and fixed strict TypeScript blockers.

**Tracking:** #1.

### P0 — IPC contract duplication and privileged capability surface

**Finding:** Renderer declarations, preload methods, and main handlers independently described the API. Runtime handler arguments were trusted. Shell/filesystem/process capabilities were broader than necessary.

**Action:** Added `src/shared/ipc.ts` as the shared contract, runtime sanitizers, sender validation, deny-by-default navigation/window behavior, typed preload bridge, exact listener cleanup, and HTTPS-only external URL policy.

**Residual:** File read capability is still path-based and cannot be fully origin-bound while legacy drag-and-drop relies on Electron 28 `File.path`. Resolve with #7.

**Tracking:** #2, #7.

### P0 — Shell command injection / process control

**Finding:** Model deletion and installer execution used shell command strings derived from renderer data. Ollama stop behavior could kill Ollama processes not owned by the application.

**Action:** Ollama CLI operations now use executable + argument arrays with shell disabled. Normal shutdown tracks/stops only the app-owned child process. Installer execution is restricted to the exact path downloaded by the current app session.

**Tracking:** #2, #3.

### P0 — Broken cancellation and retry lifecycle

**Finding:** Renderer Stop only set a queue flag; active HTTP generation continued. Readiness timeout/error paths could create duplicate retry branches. Unexpected response behavior could leave ambiguous lifecycle state.

**Action:** Added request IDs, active HTTP request tracking, real request destruction on cancel, single bounded readiness loop, and batch setting snapshots.

**Tracking:** #3.

### P1 — Keyboard/queue behavior mismatch

**Finding:** `Ctrl+O` opened a dialog and discarded results. `Ctrl+Enter` depended on missing `selectedImage`. Escape comments implied cancellation but did not cancel active processing.

**Action:** Keyboard shortcuts now reuse real queue state/actions and Escape calls actual cancellation.

**Tracking:** #4.

### P1 — Panel-state contract drift

**Finding:** `panels.presets.visible` was ignored; fixed left/right/bottom containers could reserve layout space when child panels were hidden.

**Action:** Layout now derives container existence from actual child visibility and honors presets visibility.

**Tracking:** #4.

### P1 — Preview race, MIME mismatch, and memory amplification

**Finding:** Preview async reads could race when selection changed quickly. All previews were labeled PNG regardless of source format. Full base64 data was duplicated in local state and Zustand.

**Action:** Added MIME-aware read results, stale-load cancellation, and removed redundant base64 storage from the image entity.

**Residual:** Preview still reads full source images into memory; bounded thumbnail generation remains a worthwhile optimization for very large files.

**Tracking:** #5.

### P1 — Numeric option corruption

**Finding:** Empty/invalid number inputs could create `NaN`, which could then reach persisted state or generation input.

**Action:** UI numeric updates now ignore non-finite values and clamp exposed controls to their supported ranges. Main-process input sanitization also rejects non-finite numbers.

**Residual:** Shared sanitization should remain the final authority if more options/custom preset import paths are added.

**Tracking:** #6.

### P1 — Obsolete Windows host probing

**Finding:** CPU usage depended on `wmic`, which is removed/optional on modern Windows, and port probing parsed shell `netstat` output.

**Action:** Replaced both with the already-declared `systeminformation` dependency.

**Tracking:** #6.

### P0 — Vulnerable dependency tree

**Finding:** First Windows CI `npm ci` reported 32 known vulnerabilities: 3 low, 3 moderate, 24 high, and 2 critical. Deprecated transitive packages were also reported.

**Action:** Dedicated remediation issue created instead of applying `npm audit fix --force` blindly.

**Tracking:** #10.

### P1 — Obsolete Electron line

**Finding:** Electron 28 is far behind the current stable line and lacks current Chromium/Node security updates. A direct upgrade is not safe because Electron 32 removed the non-standard `File.path` used by current drag-and-drop.

**Action:** Upgrade isolated into a dedicated issue after baseline stability. Migration must first move drag/drop path resolution to preload `webUtils.getPathForFile` or an equivalent supported design.

**Tracking:** #7.

### P1 — Dead dependencies/state and persistence evolution

**Finding:** `canvas` and `electron-store` appear unused. Persisted `autoSave`/`outputDirectory` state is not coherently connected to behavior. Persist middleware has no explicit version/migration strategy.

**Action:** Documented and tracked; dependency removal requires lockfile-safe update and security audit classification.

**Tracking:** #6, #10.

### P1 — Missing runtime tests

**Finding:** The repository had zero automated tests. The new unit/TypeScript baseline still does not execute an Electron window or real Ollama inference.

**Action:** Added durable pure-contract tests and Windows CI. Planned next layer is Playwright Electron smoke/E2E plus a real local Ollama Windows smoke checklist.

**Tracking:** #1, #8; follow-up tooling should be explicit rather than silently expanding the fast CI gate.

## Recommended tooling after green baseline

### Biome

Use for repository-wide linting and formatting if adopted. Keep strict `tsc` as type authority; Biome should complement, not replace, TypeScript checks.

### Knip

Use for dead files, unused exports, and unused dependency discovery. Particularly relevant to `canvas`, `electron-store`, stale store fields, and future renderer component cleanup.

### Playwright Electron

Use for Windows smoke/E2E: app launch, preload bridge availability, native file selection, queue insertion, generation cancellation, panel visibility, and basic packaged runtime behavior.

## Release confidence rule

Do not call this repository release-ready from a green `tsc` or unit test alone. Minimum release evidence after this migration should be:

1. `npm ci` succeeds from the lockfile on Windows.
2. `npm run check` passes.
3. `npm run build` passes.
4. Windows Electron smoke test passes.
5. Real Ollama inference smoke test passes for at least one supported vision model.
6. High/critical dependency advisories are remediated or explicitly accepted with rationale.
7. Electron support/upgrade state is documented for the release.
